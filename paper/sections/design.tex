\section{\sys{} Design}\label{sec:design}

\subsection{System Overview and Architecture}\label{sec:design:overview}

\sys{} consists of one coordinator and a set of heterogeneous edge workers.
The coordinator profiles the workers, selects an active layer placement
$\psi$, assigns backup workers through a recovery mapping $R$, and manages
request recovery.  The placement partitions the decoder into contiguous
stages.  An active worker stores its stage weights and the request KV cache,
whereas a worker selected by $R$ reserves memory and preloads the weights of
the stage that it may need to replace.  The coordinator is outside the
protection domain; the current design targets fail-stop worker failures.

During normal decoding, an activation passes through the active stages in
layer order.  Each protected non-head stage also sends its newly appended KV
bytes to the coordinator.  The coordinator combines columns from the same
request and token position into one or two cross-stage parity columns.  It
also retains the input activation required to execute the current position at
a replacement stage.  These two forms of state serve different purposes:
parity restores the completed KV prefix, while the mirrored activation starts
execution at the point where the failed stage stopped.  On failure, the
coordinator reconstructs the lost KV, activates the assigned backup, installs
the recovered state, and rewires the pipeline.

The architecture therefore separates two conditions that a recovery path must
satisfy.  The request state must be reconstructable, and a surviving worker
must have enough memory to execute the failed layer range.  Cross-stage parity
addresses the first condition.  Recovery-aware placement addresses the
second by admitting only $(\psi,R)$ pairs whose active and backup weights fit
together.

\subsection{Execution and Recovery Model}\label{sec:design:model}

Let $\mathcal{S}$ denote the protected non-head stages and let $F\subseteq
\mathcal{S}$ be the stages lost in one failure event.  A deployment configured
with $k$ parity columns admits the parity path when $0<|F|\leq k$.  The current
implementation supports $k\in\{1,2\}$: one parity column protects one failed
stage, and two columns protect two simultaneous failed stages.  We assume an
unannounced process crash, out-of-memory termination, or network partition is
observed as a fail-stop event.  Byzantine corruption, coordinator failure, a
head-stage failure, and more than $k$ simultaneous protected-stage failures
are outside this guarantee.

A failure count within the configured limit is necessary but not sufficient.
Before decoding parity, the coordinator checks that (i) every failed stage is
protected, (ii) the surviving KV columns have valid per-position lengths,
(iii) the parity entries for the common completed prefix are complete, (iv)
the mirrored input for the interrupted position is present, and (v) $R$
identifies a live worker with the required weights loaded.  These checks form
the recovery contract.  If the contract does not hold, \sys{} first attempts
failed-stage replay using the retained stage inputs and then falls back to
full-prefix replay.  Only a completed parity path carries the bit-exact
KV-state guarantee; replay fallbacks regenerate the state through model
execution.

The recovery mapping cannot be appended after an otherwise independent
placement decision.  Assigning more layers to a fast worker increases both
its active weight footprint and the reservation required on its backup.  A
placement that fits during normal execution can therefore leave no surviving
worker able to host the failed stage.  Section~\ref{sec:design:dp} accounts for
this coupling while constructing $\psi$.

\subsection{Cross-Stage KV Parity}\label{sec:design:parity}

For request $r$ and completed token position $q$, let $D_s[r,q]$ be the
serialized KV bytes appended by protected stage $s\in\mathcal{S}$, and let
$\ell_s$ be its unpadded length.  Stage sizes can differ because the placement
may assign different numbers of layers to different workers.  \sys{} pads
each column to $\ell_{\max}=\max_{s\in\mathcal{S}}\ell_s$ before encoding and
records $\ell_s$ so that recovered bytes can be trimmed before installation.
With one parity column, the coordinator stores
\begin{equation}\label{eq:single-parity}
  P[r,q] = \bigoplus_{s\in\mathcal{S}}
            \operatorname{pad}\!\left(D_s[r,q]\right).
\end{equation}
An update is applied at most once for each $(r,q,s)$ tuple.  The coordinator
marks $P[r,q]$ complete only after it has received a column from every stage in
$\mathcal{S}$, preventing a partial XOR value from being used for recovery.

For $k=2$, \sys{} stores a second column over $\mathrm{GF}(2^8)$.  Each stage
has a distinct nonzero coefficient $a_s=g^{\operatorname{rank}(s)}$, where
$g$ is a primitive field element, and
\begin{equation}\label{eq:double-parity}
  Q[r,q] = \bigoplus_{s\in\mathcal{S}}
            a_s\otimes\operatorname{pad}\!\left(D_s[r,q]\right).
\end{equation}
All operations are byte-wise, so the worker-side KV representation does not
change.  A single-parity entry occupies $\ell_{\max}$ bytes per position and
a double-parity entry occupies $2\ell_{\max}$ bytes, compared with
$\sum_{s\in\mathcal{S}}\ell_s$ bytes for one full replica of every protected
column.

\subsection{KV Recovery and Fallback}\label{sec:design:recovery}
\label{sec:design:mirror}

After identifying $F$, the coordinator fetches the surviving KV columns and
checks their slot geometry.  A surviving byte stream must be divisible by its
expected bytes per position.  Under synchronous pipeline execution, adjacent
stages may differ by one completed slot because an upstream stage can finish
the interrupted position before the failure propagates.  A larger difference
indicates inconsistent state.  \sys{} therefore recovers only the common
completed prefix $N$, defined by the minimum valid slot count, and requires a
complete parity entry for every $q<N$.

For one failed stage $x$, each prefix column is recovered as
\begin{equation}\label{eq:recover-single}
  \widehat{D}_x[r,q] = \operatorname{trim}_{\ell_x}\!\left(
  P[r,q]\oplus\!\bigoplus_{s\in\mathcal{S}\setminus\{x\}}
  \operatorname{pad}\!\left(D_s[r,q]\right)\right).
\end{equation}
For two failed stages $x$ and $y$, the surviving columns are first removed
from $P$ and $Q$, yielding
$\widetilde{P}=D_x\oplus D_y$ and
$\widetilde{Q}=a_x\otimes D_x\oplus a_y\otimes D_y$.  The coordinator solves
the resulting two-equation system byte by byte:
\begin{align}
  \widehat{D}_x &=(\widetilde{Q}\oplus
    a_y\otimes\widetilde{P})\oslash(a_x\oplus a_y),
    \label{eq:recover-double-x}\\
  \widehat{D}_y &=\widetilde{P}\oplus\widehat{D}_x.
    \label{eq:recover-double-y}
\end{align}

Algorithm~\ref{alg:cross-stage-parity} summarizes the guarded recovery path.
After the reconstructed prefix has been installed on the backup, the
coordinator executes the interrupted position once using its mirrored input
activation and then continues with the next decode step.  Positions preceding
the failure are not forwarded through the failed layer range again.  If any
contract check fails, the algorithm returns to the replay ladder instead of
using incomplete or inconsistent parity state.

\begin{algorithm}[t]
  \caption{Guarded cross-stage parity recovery}
  \label{alg:cross-stage-parity}
  \begin{algorithmic}[1]
    \Require Request $r$, failed set $F$, interrupted position $q_f$
    \If{$F\nsubseteq\mathcal{S}$ or $|F|=0$ or $|F|>k$}
      \State \Return \Call{ReplayFallback}{$r,F$}
    \EndIf
    \State Fetch surviving KV and derive their slot counts
    \If{slot geometry is invalid or the count spread exceeds one}
      \State \Return \Call{ReplayFallback}{$r,F$}
    \EndIf
    \State $N\gets$ minimum surviving slot count
    \If{parity is incomplete for some $q<N$}
      \State \Return \Call{ReplayFallback}{$r,F$}
    \EndIf
    \If{the input at $q_f$ or a live loaded backup is missing}
      \State \Return \Call{ReplayFallback}{$r,F$}
    \EndIf
    \For{$q\gets0$ to $N-1$}
      \State Recover $D_s[r,q]$ for $s\in F$ using
      Eq.~\ref{eq:recover-single} or Eqs.~\ref{eq:recover-double-x}--\ref{eq:recover-double-y}
    \EndFor
    \State Install recovered KV and activate the backup stage
    \State Execute $q_f$ once from the mirrored input; rewire the chain
    \State \Return resume decoding at $q_f+1$
  \end{algorithmic}
\end{algorithm}

\subsection{Recovery-Aware Layer Placement}\label{sec:design:dp}

Let $L$ be the number of decoder layers and $D$ the available workers.  A
candidate placement partitions the layers into contiguous stages assigned to
an ordered subset of $D$.  For a stage containing layers $i$ through $j$ on
worker $d$, let $c(i,j,d)$ include its profiled execution time and the cost of
receiving its input from the preceding stage.  The placement DP maintains the
sum of stage costs, $z_{\Sigma}$, and the slowest stage cost, $z_{\max}$.  The
configured optimization mode ranks a candidate by
\begin{equation}\label{eq:rank}
  \rho(z_{\Sigma},z_{\max})=
  \begin{cases}
    z_{\max}, & \text{throughput},\\
    z_{\Sigma}, & \text{latency},\\
    z_{\Sigma}+\alpha z_{\max}, & \text{blended}.
  \end{cases}
\end{equation}
This retains both cumulative latency and bottleneck time in the DP state
instead of converting one into a fixed additive increment.

For a fixed device order $(d_1,\ldots,d_n)$, let
$A[y,n]=(A_{\Sigma}[y,n],A_{\max}[y,n])$ be the best state after placing the
first $y$ layers on the first $n$ devices.  For a final split after layer
$l$, define
\begin{align*}
  z_{\Sigma}(l) &= A_{\Sigma}[l,n-1]+c(l+1,y,d_n),\\
  z_{\max}(l) &= \max\{A_{\max}[l,n-1],c(l+1,y,d_n)\},\\
  z(l) &= (z_{\Sigma}(l),z_{\max}(l)).
\end{align*}
The recurrence is
\begin{equation}\label{eq:dp}
  A[y,n]=z(l^*),\qquad
  l^*=\underset{\substack{n-1\leq l<y\\\text{feasible}}}
  {\arg\min}\;\rho\!\left(z(l)\right).
\end{equation}
Candidate device orders supply subset selection.  As in heterogeneous
partitioning systems such as EdgeShard and Jupiter, the resulting objective
can prioritize end-to-end latency or the slowest pipeline stage
~\cite{zhang2024edgeshard,ye2025jupiter}.

Recovery changes the feasible set.  Let $W_{\psi}(d)$ be the active weights
placed on device $d$, $W_{\psi}(s)$ the weights in stage $s$, and $M(d)$ the
usable model-memory capacity.  Every candidate must satisfy
\begin{equation}\label{eq:mem}
  W_{\psi}(d)+\sum_{s:R(s)=d}W_{\psi}(s)\leq M(d),
  \qquad \forall d\in D.
\end{equation}
The second term is the memory reserved for backup weights.  Because the stage
intervals determine this term while the reservations constrain the next
placement, \sys{} alternates between constructing $R$ and solving the
placement DP.  Each new pair is checked with its actual stage intervals, and
the bounded search returns the best self-consistent pair found; it does not
assume that every alternating step improves the objective.

\begin{algorithm}[t]
  \caption{Recovery-aware alternating placement}
  \label{alg:recovery-aware-dp}\label{alg:alt}
  \begin{algorithmic}[1]
    \Require Workers $D$, layer count $L$, iteration limit $I_{\max}$
    \State $\psi\gets$ \Call{InitialPlacement}{$D,L$}; $B\gets\bot$
    \State $R_{\mathrm{prev}}\gets\bot$
    \For{$i\gets1$ to $I_{\max}$}
      \State $R\gets$ \Call{BuildRecovery}{$\psi$}
      \State $\psi'\gets$ \Call{PlacementDP}{$D,L,R,\psi$}
      \If{$\psi'=\bot$}
        \State \textbf{break}
      \EndIf
      \If{\Call{RecoveryFeasible}{$\psi',R$}}
        \State $B\gets$ better of $B$ and $(\psi',R)$ under Eq.~\ref{eq:rank}
      \EndIf
      \If{$\psi'=\psi$ and $R=R_{\mathrm{prev}}$}
        \State \textbf{break}
      \EndIf
      \State $\psi\gets\psi'$; $R_{\mathrm{prev}}\gets R$
    \EndFor
    \State \Return $B$
  \end{algorithmic}
\end{algorithm}

\subsection{Runtime Integration}\label{sec:design:runtime}
\label{sec:design:async}

At deployment time, the coordinator profiles layer execution and peer links,
runs Algorithm~\ref{alg:alt}, loads the active stage weights, and preloads the
backup weights selected by $R$.  During decoding, workers retain their local
KV cache and report the new protected KV column after each completed position.
Parity updates and input mirrors are keyed by request and position, making
duplicate delivery idempotent and preventing state from different decode
steps from being combined.

The coordinator detects worker loss through the request RPC path or heartbeat.
The failure report carries the original failed layer interval, which is
resolved against the active placement rather than a partially rewired chain.
The coordinator then freezes progress for the affected request, applies the
contract in Algorithm~\ref{alg:cross-stage-parity}, promotes the backup, and
updates the neighboring stage routes.  Normal execution may use synchronous or
asynchronous chain forwarding; the recovery state and placement constraints
are unchanged, while asynchronous forwarding relies on heartbeat when an RPC
trailer can no longer propagate the failed interval.

The prototype is implemented in Python with PyTorch and gRPC.  Workers expose
stage loading, execution, KV transfer, backup promotion, routing, profiling,
and health-check operations.  The coordinator owns placement, parity state,
failure attribution, and request-level recovery, keeping the worker data path
limited to stage execution and state transfer.
