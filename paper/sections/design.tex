\section{\sys{} Design}\label{sec:design}

\subsection{System Overview and Architecture}\label{sec:design:overview}

\begin{figure}[t]
  \centering
  \includegraphics[width=\linewidth]{paper/fig_architecture.pdf}
  \caption{\sys{} architecture.  The coordinator places layers and backups
  ($\psi$, $R$), folds the protected stages' KV columns into parity, retains
  stage inputs, and detects failures; each worker serves one stage and
  preloads the backup weights $R$ assigns to it (dashed; a device may host
  two backups or none).  The shaded head stage ships no KV column, and the
  coordinator itself is unprotected.}
  \label{fig:architecture}
\end{figure}

\sys{} consists of one coordinator and a set of heterogeneous edge workers
(Fig.~\ref{fig:architecture}).
The coordinator profiles the workers, selects an active layer placement
$\psi$, assigns backup workers through a recovery mapping $R$ that gives every
stage $s$, the head included, a backup device $R(s)\in\mathcal{D}$ other
than the one serving it (parity protects only the non-head stages
$\mathcal{S}$; the head's backup serves replay), and manages request
recovery.  The placement partitions the decoder into contiguous
stages.  An active worker stores its stage weights and the request KV cache,
whereas a worker selected by $R$ reserves memory and preloads the weights of
the stage that it may need to replace.  The coordinator is outside the
protection domain; the current design targets fail-stop worker failures.

During normal decoding, an activation passes through the active stages in
layer order, and each protected non-head stage also sends its newly appended
KV bytes to the coordinator, which folds columns of the same request and
token position into one or two cross-stage parity columns and retains the
input activation of the current position (the prototype keeps the
per-position history that the replay ladder needs, Section~\ref{sec:eval:footprint}).  Parity restores the completed KV
prefix; the mirrored activation restarts execution where the failed stage
stopped.  On failure, the coordinator reconstructs the lost KV, activates the
assigned backup, installs the recovered state, and rewires the pipeline.  A
recovery path must therefore satisfy two conditions, a reconstructable
request state and a surviving worker with memory for the failed layer range;
cross-stage parity addresses the first, and recovery-aware placement the
second by admitting only $(\psi,R)$ pairs whose active and backup weights
fit together.

\subsection{Execution and Recovery Model}\label{sec:design:model}

Let $\mathcal{S}$ denote the protected non-head stages and let $F\subseteq
\mathcal{S}$ be the stages lost in one failure event.  A deployment configured
with $k$ parity columns admits the parity path when $0<|F|\leq k$.  The current
implementation supports $k\in\{1,2\}$: one parity column protects one failed
stage, and two columns protect two simultaneous failed stages.  We assume an
unannounced process crash, out-of-memory termination, or network partition is
observed as a fail-stop event.  Byzantine corruption, coordinator failure, a
head-stage failure, and more than $k$ simultaneous protected-stage failures
are outside this guarantee.  A partitioned worker that later returns is
not fenced by the prototype, and $R$ does not model shared failure domains.

A failure count within the limit is necessary but not sufficient.  Before
decoding parity, the coordinator checks the \emph{recovery contract}: (i)
every failed stage is protected, (ii) the surviving KV columns have valid
per-position lengths, (iii) the parity entries for the common completed
prefix are complete, (iv) the mirrored input for the interrupted position is
present, and (v) $R$ identifies a live worker with the required weights
loaded.  Otherwise \sys{} attempts failed-stage replay from the retained
stage inputs and then full-prefix replay; only a completed parity path
carries the bit-exact KV-state guarantee.

The recovery mapping cannot be appended after an independent placement
decision: assigning more layers to a fast worker increases both its active
footprint and the reservation required on its backup, so a placement that
fits during normal execution can leave no surviving worker able to host the
failed stage.  Section~\ref{sec:design:dp} accounts for this coupling while
constructing $\psi$.

\subsection{Cross-Stage KV Parity}\label{sec:design:parity}

For request $r$ and completed token position $q$, let $D_s[r,q]$ be the
serialized KV bytes appended by protected stage $s\in\mathcal{S}$, and let
$\ell_s$ be its unpadded length.  Stage sizes can differ because the placement
may assign different numbers of layers to different workers.  \sys{} pads
each column to $\ell_{\max}=\max_{s\in\mathcal{S}}\ell_s$ before encoding and
records $\ell_s$ so that recovered bytes can be trimmed before installation.
With one parity column, the coordinator stores
\begin{equation}\label{eq:single-parity}
  P[r,q] = \bigoplus_{s\in\mathcal{S}}
            \operatorname{pad}\!\left(D_s[r,q]\right).
\end{equation}
An update is applied at most once for each $(r,q,s)$ tuple.  The coordinator
marks $P[r,q]$ complete only after it has received a column from every stage in
$\mathcal{S}$, preventing a partial XOR value from being used for recovery.

For $k=2$, \sys{} stores a second column over the Galois field
$\mathrm{GF}(2^8)$.  Each stage has a distinct nonzero coefficient $a_s=g^{\operatorname{rank}(s)}$, where
$g$ is a primitive field element, and
\begin{equation}\label{eq:double-parity}
  Q[r,q] = \bigoplus_{s\in\mathcal{S}}
            a_s\otimes\operatorname{pad}\!\left(D_s[r,q]\right).
\end{equation}
All operations are byte-wise, so the worker-side KV representation does not
change.  A single-parity entry occupies $\ell_{\max}$ bytes per position and
a double-parity entry occupies $2\ell_{\max}$ bytes, compared with
$\sum_{s\in\mathcal{S}}\ell_s$ bytes for one full replica of every protected
column.

\subsection{KV Recovery and Fallback}\label{sec:design:recovery}
\label{sec:design:mirror}

After identifying $F$, the coordinator fetches the surviving KV columns and
checks their slot geometry: each byte stream must be divisible by its bytes
per position, and adjacent stages may differ by one completed slot, since an
upstream stage can finish the interrupted position before the failure
propagates; a larger difference indicates inconsistent state.  \sys{}
recovers only the common completed prefix $N$, the minimum valid slot count,
and requires a complete parity entry for every $q<N$.

For one failed stage $x$, each prefix column is recovered as
\begin{equation}\label{eq:recover-single}
  \widehat{D}_x[r,q] = \operatorname{trim}_{\ell_x}\!\left(
  P[r,q]\oplus\!\bigoplus_{s\in\mathcal{S}\setminus\{x\}}
  \operatorname{pad}\!\left(D_s[r,q]\right)\right).
\end{equation}
For two failed stages $x$ and $y$, the surviving columns are first removed
from $P$ and $Q$, yielding
$\widetilde{P}=D_x\oplus D_y$ and
$\widetilde{Q}=a_x\otimes D_x\oplus a_y\otimes D_y$.  The coordinator solves
the resulting two-equation system byte by byte, the standard two-erasure
decoding of a Reed--Solomon code~\cite{plank1997tutorial}:
\begin{align}
  \widehat{D}_x &=(\widetilde{Q}\oplus
    a_y\otimes\widetilde{P})\oslash(a_x\oplus a_y),
    \label{eq:recover-double-x}\\
  \widehat{D}_y &=\widetilde{P}\oplus\widehat{D}_x.
    \label{eq:recover-double-y}
\end{align}

Algorithm~\ref{alg:cross-stage-parity} summarizes the guarded path.  After
the reconstructed prefix is installed on the backup, the coordinator executes
the interrupted position once from its mirrored input and continues with the
next decode step; positions before the failure are never forwarded through
the failed layer range again, and any contract failure returns to the replay
ladder.

\begin{algorithm}[t]
  \caption{Guarded cross-stage parity recovery}
  \label{alg:cross-stage-parity}
  \begin{algorithmic}[1]
    \Require Request $r$, failed set $F$, interrupted position $q_f$
    \If{$F\nsubseteq\mathcal{S}$ or $|F|=0$ or $|F|>k$}
      \State \Return \Call{ReplayFallback}{$r,F$}
    \EndIf
    \State Fetch surviving KV; $N\gets$ minimum valid slot count
    \If{slot geometry invalid, spread $>1$, parity incomplete for some
      $q<N$, input at $q_f$ missing, or no live loaded backup}
      \State \Return \Call{ReplayFallback}{$r,F$}
    \EndIf
    \For{$q\gets0$ to $N-1$}
      \State Recover $D_s[r,q]$ for $s\in F$ using
      Eq.~\ref{eq:recover-single} or Eqs.~\ref{eq:recover-double-x}--\ref{eq:recover-double-y}
    \EndFor
    \State Install recovered KV and activate the backup stage
    \State Execute $q_f$ once from the mirrored input; rewire the chain
    \State \Return resume decoding at $q_f+1$
  \end{algorithmic}
\end{algorithm}

\subsection{Recovery-Aware Layer Placement}\label{sec:design:dp}

Let $L$ be the number of decoder layers and $\mathcal{D}$ the available workers.  A
candidate placement partitions the layers into contiguous stages assigned to
an ordered subset of $\mathcal{D}$.  For a stage containing layers $i$ through $j$ on
worker $d$, let $t(i,j,d)$ include its profiled execution time and the cost of
receiving its input from the preceding stage.  The placement dynamic program (DP) maintains the
sum of stage costs, $z_{\Sigma}$, and the slowest stage cost, $z_{\max}$.  The
configured optimization mode ranks a candidate by
\begin{equation}\label{eq:rank}
  \rho(z_{\Sigma},z_{\max})=
  \begin{cases}
    z_{\max}, & \text{throughput},\\
    z_{\Sigma}, & \text{latency},\\
    z_{\Sigma}+\alpha z_{\max}, & \text{blended}.
  \end{cases}
\end{equation}
This keeps both cumulative latency and bottleneck time in the DP state; the
recurrence is exact for the throughput and latency modes and a heuristic for
the blended mode, whose objective lacks optimal substructure; $\alpha$ is a
configured weight, and the evaluation uses the throughput mode.

For a fixed device order $(d_1,\ldots,d_n)$, let
$A[y,n]=(A_{\Sigma}[y,n],A_{\max}[y,n])$ be the best state after placing the
first $y$ layers on the first $n$ devices.  For a final split after layer
$l$, define
\begin{align*}
  z_{\Sigma}(l) &= A_{\Sigma}[l,n-1]+t(l+1,y,d_n),\\
  z_{\max}(l) &= \max\{A_{\max}[l,n-1],t(l+1,y,d_n)\},\\
  z(l) &= (z_{\Sigma}(l),z_{\max}(l)).
\end{align*}
The recurrence is
\begin{equation}\label{eq:dp}
  A[y,n]=z(l^*),\qquad
  l^*=\underset{\substack{n-1\leq l<y\\\text{feasible}}}
  {\arg\min}\;\rho\!\left(z(l)\right).
\end{equation}
Candidate device orders supply subset selection, and as in EdgeShard and
Jupiter the objective can prioritize end-to-end latency or the slowest
stage~\cite{zhang2024edgeshard,ye2025jupiter}.

Recovery changes the feasible set.  Let $W_{\psi}(d)$ be the active weights
placed on device $d$, $W_{\psi}(s)$ the weights in stage $s$, and $M(d)$ the
usable model-memory capacity.  Every candidate must satisfy
\begin{equation}\label{eq:mem}
  W_{\psi}(d)+\sum_{s:R(s)=d}W_{\psi}(s)\leq M(d),
  \qquad \forall d\in\mathcal{D}.
\end{equation}
The second term is the memory reserved for backup weights; Eq.~\ref{eq:mem}
charges weights only, and the KV cache installed on a backup at recovery
time is working memory of the request rather than a placement reservation.  Because the
stage intervals determine this term while the reservations constrain the
next placement, \sys{} alternates: starting from a uniform placement, each
iteration builds $R$ for the current $\psi$, re-solves the DP with that $R$
as the backup burden, keeps the pair if it satisfies Eq.~\ref{eq:mem} under
its own reservations and ranks better under Eq.~\ref{eq:rank}, and stops
when $\psi$ and $R$ repeat or after ten iterations,
returning the best self-consistent pair; the alternation is a heuristic
without an optimality guarantee.  Every ordered device subset is enumerated around this loop (1\,950 on the
six-worker fleet, $\sum_{k=2}^{|\mathcal{D}|}P(|\mathcal{D}|,k)$ in general,
about 9.9 million at ten devices); the 7B solve took 122\,s on this fleet.


\subsection{Runtime Integration}\label{sec:design:runtime}
\label{sec:design:async}

At deployment time the coordinator profiles layer execution and peer links,
runs the alternating search, loads the active stage weights, and preloads the
backup weights selected by $R$.  Parity updates and input mirrors are keyed by
request and position, so duplicate delivery is idempotent.  Worker loss is
detected through the request remote procedure call (RPC) path, whose trailer
carries the failed layer interval, or through heartbeat (1\,s ticks, 5\,s timeout) under asynchronous
forwarding; the coordinator then freezes the affected request, applies the
contract in Algorithm~\ref{alg:cross-stage-parity}, promotes the backup, and
updates the neighboring routes.  The prototype is Python with PyTorch and gRPC; the coordinator owns
placement, parity state, failure attribution, and recovery, and the worker
data path is limited to stage execution and state transfer.
