% Paragraph 1: when L>T could lose; bounded-claim honesty.
% - L+async is best on this fleet at C>=4, but the single-stream
%   big-model regime has a measured cross-over: on Llama-3.2-1B
%   at C=1, T+async beats L+async on aggregate throughput by
%   +22% (3.74 vs 3.05 tok/s) even though L still wins TBT p50
%   by -33%. The intuition: when a stage's compute time dominates
%   chain-hop cost (bigger model, single in-flight stream), L's
%   fast-device-heavy placement makes that single stage the
%   throughput-bottlenecking critical path, while T's even
%   division saturates wall-clock. Multi-stream amortises the
%   chain hop and L's pipeline-saturation advantage returns.
%   Additional regimes where T could re-take the lead — AGX
%   running out of memory before the Nano's layer-floor binds,
%   models deep enough that bulk-on-AGX overflows (hypothetical
%   Llama-7B INT4 with 7 layers per Nano), bandwidth-dominated
%   networks — remain extrapolations from the cost model.
%   Operators tune via `optimization_mode = blended` with a
%   sweepable $\alpha$.

% Paragraph 2: async chain failure-attribution trade-off.

%   doesn't, R+psi feasibility preserves correctness but charges
%   an extra hop. Sync chain is the right choice when failure
%   attribution must be millisecond-tight; async when steady-state
%   throughput dominates.
