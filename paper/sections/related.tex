% Edge LLM inference: Petals~\cite{petals2023} demonstrated
% collaborative inference on consumer hardware with greedy
% placement and redundancy-based recovery, but its 16+~GB peer
% assumption excludes 4~GB Nano. EdgeShard~\cite{edgeshard2024}
% adds a DP-based latency-optimal placement (our $\alpha=0$
% boundary) but assumes a redundant copy of each shard exists; its
% recovery story is implicit. Jupiter~\cite{jupiter2024} introduces
% throughput-optimal pipeline parallelism (our $\alpha=1$ boundary,
% Eq.~11) and TBT-SLO constraints but offers no recovery and no
% chain forwarding. Helix~\cite{helix2024} measures greedy
% placement's 2.38$\times$ throughput tax on heterogeneous fleets,
% motivating our DP-based approach. RADP unifies these threads:
% the same DP yields EdgeShard's or Jupiter's placement via the
% $\alpha$ knob, and our async mirror cache + chain-aware recovery
% adds fault tolerance neither prior system provides on
% memory-tight edge. Among pipeline-parallel training systems
% (GPipe~\cite{gpipe2019}, Megatron) and inference engines
% (vLLM~\cite{vllm2023}), only vLLM is request-granular, and even
% it assumes a single-GPU executor — none address chain-stage
% recovery on a multi-host edge fleet.
