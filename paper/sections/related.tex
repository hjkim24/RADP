\section{Related Work}\label{sec:related}

\subsection{Edge-distributed LLM inference}
% - Petals: greedy placement across a public swarm. Memory-permissive
%   (assumes >=16 GB nodes). Has redundancy-based recovery but treats
%   placement and redundancy as decoupled.
% - EdgeShard: DP-based optimal placement (latency mode). No
%   recovery model. Authors assume a redundant copy of each shard
%   sits somewhere on the cluster, which is exactly the
%   assumption we cannot afford on 4 GB Nano.
% - Jupiter: throughput-mode DP (Eq. 11 sets our throughput
%   baseline). Coordinator-mediated star topology, no chain
%   forwarding, no recovery.
% - Llama.cpp + RPC: model-parallel via a wrapper protocol on
%   CPU-class devices. No placement DP. Cited as the de-facto
%   "just split it across what you have" baseline.

\subsection{Fault tolerance for distributed inference}

%   contexts.

%   targets a single GPU. The chain-aware attribution +
%   replay-onto-backup we propose has no analogue there.
