\section{Related Work}\label{sec:related}

\subsection{Distributed LLM Inference and Fault Tolerance}

EdgeShard profiles per-layer execution time, memory use, and inter-device
communication cost, then assigns consecutive layers to a selected set of
heterogeneous edge and cloud devices so as to minimize either cumulative
stage time or the slowest stage~\cite{zhang2024edgeshard}.  Jupiter likewise
partitions decoder layers across heterogeneous edge devices under memory and
token-between-time constraints and adds intra-sequence pipeline-parallel
prefill and speculative decoding~\cite{ye2025jupiter}.  Both determine the
active placement but reserve neither KV redundancy nor executable backup
capacity, so a failed device removes its layer range together with the
request state stored there.  Heterogeneity-aware placement is also
established for datacenter GPU clusters: Helix, HexGen, HexGen-2, Hetis, and
LLM-PQ solve placement, parallelism, or quantization as a coupled
optimization over GPUs of different classes~\cite{mei2025helix,
jiang2024hexgen,jiang2025hexgen2,mo2025hetis,zhao2024llmpq}.  These systems
assume datacenter memory and restore no in-flight request state; HexGen
reacts to a departed GPU by re-running its placement search.  For
heterogeneous edge pipelines, fault tolerance has been addressed in training,
where FTPipeHD replicates weights and re-partitions the pipeline after a
failure~\cite{chen2024ftpipehd}; its recovery unit is model weights and its
budget a training batch, whereas decoding must restore per-request KV state
within a token interval.  JARVIS considers failures in a tactical edge
network and proposes layer redundancy and peer-level retrieval, but its
prototype evaluates route reconfiguration and layer skipping, a degraded
execution whose effect depends on the bypassed layer~\cite{sirera2024jarvis};
automatic failover and recovery-aware placement remain unaddressed.

\subsection{Recomputation}

Recomputation rebuilds lost KV state by executing model layers again.  Petals
keeps, on the client, the inputs sent to each remote block range; when a
server disconnects, the client selects a replacement that already holds the
missing blocks, forms a new chain, and replays the cached inputs through that
block range only~\cite{borzunov2023petals,borzunov2023distributed}.  This
spares the other stages, but the failed layers still execute once per prior
position, and a peer must already store the same block range, which is
infeasible when every device is needed to hold one part of the model.
Petals' server-side block rebalancing is a separate protocol and not the
algorithm that repairs an interrupted route.  Our Recompute baseline
(Section~\ref{sec:eval:setup}) is the corresponding lower bound on retained
state: it replays every stage from position zero.

\subsection{Replication}

DejaVu streams each pipeline worker's KV cache to a replica and tracks
replicated progress per token; after a failure the replacement restores the
latest acknowledged replica and recomputes only the unreplicated
tail~\cite{strati2024dejavu}.  Protecting all stages therefore stores the sum
of their KV caches.  KevlarFlow copies PagedAttention KV blocks in the
background to another warm pipeline instance that already holds the same
stage weights~\cite{qian2026kevlarflow}, and LUMEN places request checkpoints
in host memory on load-aware holders that each hold a complete
model~\cite{cao2026lumen}.  Both retain KV state to avoid prefix
recomputation, but neither places active layer partitions and backup weights
jointly across devices that cannot each hold the full model.

\subsection{Reconfiguration}

SpotServe replans data, tensor, and pipeline parallelism when a cloud
provider announces preemption, using bipartite matching to reuse parameters
and KV context and migrating that context before the instance is
lost~\cite{miao2024spotserve}; without advance notice its KV context may be
lost and recovery falls back to loading weights.  Parallax serves LLMs over a
decentralized pool of heterogeneous GPUs and handles GPU departure by
de-allocating its layers and re-stitching requests across
replicas~\cite{tong2025parallax}.  Both re-place after the fact, and the
grace period or replicas that spare them a cold restart are unavailable to an
unannounced edge crash.  Our Reconfigure baseline
(Section~\ref{sec:eval:setup}) measures that unassisted path.

\subsection{Parity}

GhostServe replaces full KV replicas with erasure-coded checkpoints inside a
tensor-parallel server: it generates XOR, RDP, or Reed--Solomon parity with
fused GPU kernels, stores it in host memory, and at recovery time chooses how
much prefix to recompute and how much to decode from
parity~\cite{jayakody2026ghostserve}.  Its protection domain is the GPU
shards of one node, and it assumes a large host-memory tier.  \sys{} encodes
KV columns across the protected non-head stages of a pipeline, so one parity
column occupies the size of the largest protected column rather than the
sum; a second column over the Galois field GF($2^8$) covers two simultaneous
failures; and the active placement $\psi$ and backup mapping $R$ are
selected together, with backup-weight reservations charged to the next
placement decision.  Table~\ref{tab:related-comparison} summarizes these
distinctions.
