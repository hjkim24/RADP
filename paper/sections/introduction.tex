\section{Introduction}\label{sec:intro}

\IEEEPARstart{L}{arge} language models (LLMs) are increasingly being used
for battery management, industrial fault diagnosis, visual monitoring, and
industrial-control protocol emulation~\cite{zhang2026finetuning,liu2024joint,
wang2024largescale,chamotra2026advancing}.  Many of these deployments cannot
assume an uninterrupted path to a public cloud.  Industrial operational
technology networks may be physically isolated from untrusted external
networks~\cite{hussain2025airgap}; remote and maritime sites operate over
limited or time-varying links~\cite{yuan2023elect,yang2024erocn}; and mobile
robots are sensitive to delay, packet loss, and disconnection in their control
loop~\cite{omena2023twotier}.  Keeping inference on site avoids making these
applications depend on a remote service; the site's own devices then serve
the model over their local network, and the model weights and growing
key-value (KV) cache can exceed the memory of a single edge device, or one device cannot meet
the throughput target.  Splitting consecutive
decoder layers across several devices is therefore a practical way to pool
the compute and memory already available at the site~\cite{macario2025mdi,
zhang2024edgeshard,ye2025jupiter,picano2025matching,zheng2026dybap}.  Such a deployment is inherently
heterogeneous: its pipeline may span GPUs, CPUs, and embedded accelerators
with different execution rates and memory capacities.

Distribution removes a single-device capacity bottleneck but makes each
request depend on every stage of the pipeline.  Fault-tolerant Industrial
Internet of Things routing already treats node and link failures as operating
conditions~\cite{kaur2023intelligent}, and we encountered unexpected process
exits and out-of-memory failures while operating our testbed.  For
autoregressive inference the dependence is severe: each stage retains the KV
cache produced for earlier tokens, so a failed stage loses both its assigned
computation and the request-specific state needed to continue decoding.  EdgeShard and Jupiter optimize layer
partitioning and placement across heterogeneous devices, but neither paper
specifies a runtime path that restores this lost state and resumes an in-flight
request~\cite{zhang2024edgeshard,ye2025jupiter}.  Moving the failed layer range
to another device is therefore insufficient by itself: the replacement must
also recover the current KV state before the next token can be generated.

Existing recovery mechanisms trade recovery time against the state retained
during normal operation.  Recomputation, even when limited to the failed
stage as in Petals~\cite{borzunov2023distributed}, replays model computation whose
cost grows with the prefix produced before the failure; KV replication, as in
DejaVu~\cite{strati2024dejavu}, avoids that replay but stores the sum of the
protected stages' KV caches; reactive reconfiguration stores nothing but must
reload weights and restart the request, whereas SpotServe migrates state during
an announced preemption grace period~\cite{miao2024spotserve}; and
GhostServe's erasure-coded KV checkpoints target tensor-parallel serving with
parity in host memory~\cite{jayakody2026ghostserve}.  None of these
establishes how to protect KV state across the stages of a heterogeneous,
memory-constrained edge pipeline while ensuring that a surviving device can
execute the failed stage.  Edge recovery must therefore consider
\emph{Recovery Latency}, \emph{Recovery-State Footprint}, and
\emph{Recovery Feasibility} together.

We present \emph{KV Cache Availability and Recovery at the Edge}
(\sys{}), which pairs state recovery with executable backup capacity for the failed
stage's weights.  Its first component, \emph{cross-stage parity}, encodes the KV
byte streams of protected non-head stages into one parity column.  After a
single protected-stage failure, the coordinator reconstructs the lost KV from
the parity column and the surviving stages without recomputing the prefix; the
retained redundancy is proportional to the largest protected KV column rather
than their sum.  Direct state reconstruction also has a distinct property on
heterogeneous hardware: replaying the same stage through different execution
backends can change KV bytes because operation order, precision, and kernels
differ, as a cross-tier replay experiment confirms.  We therefore treat
\emph{KV-State Fidelity} as a property of the recovered state itself; when
its validation gates pass, the parity path reconstructs the stored bytes
exactly, a guarantee that does not extend to replay fallbacks.  The second component, \emph{recovery-aware layer
placement}, ensures that the reconstructed state has somewhere to run.
\sys{} searches active layer placement and backup assignment together and
charges backup-weight reservations to each device's memory constraint.  This
coupling excludes placements that execute normally but cannot admit a valid
backup after failure.

This paper makes four contributions: it formulates fault recovery for
heterogeneous distributed LLM inference along Recovery Latency,
Recovery-State Footprint, and Recovery Feasibility, with KV-State Fidelity as
a property of the recovered state; it introduces cross-stage KV parity that
restores one failed stage without prefix recomputation and a second parity
column for two simultaneous failures; it develops a recovery-aware placement
search that folds backup assignment and backup-weight reservation into
placement feasibility; and it evaluates \sys{} on a heterogeneous Jetson
testbed against recomputation, Petals-style failed-stage replay,
DejaVu-style replication, and reactive reconfiguration.  Section~\ref{sec:related}
positions the work, Section~\ref{sec:design} presents the design,
Section~\ref{sec:eval} evaluates it, and Section~\ref{sec:disc} discusses
limitations.
