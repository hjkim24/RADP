\section{서  론}
% =======================================================================

LLM inference 를 edge cluster 에서 수행하려는 시도가 활발하다.
Petals~\cite{borzunov2023petals,borzunov2023distributed} 는 consumer
GPU swarm 에서의 collaborative inference 를 시연했고,
EdgeShard~\cite{zhang2024edgeshard} 는 DP 기반 latency-optimal layer
placement 를, Jupiter~\cite{ye2025jupiter} 는 명시적 TBT-SLO 제약
하의 throughput-optimal placement 를 추가했다. 그러나 이들 시스템은
data center 에서 통용되던 두 가지 가정에 의존한다.
첫째, \textbf{균질성}: 본 연구의 8-worker Jetson fleet 에서 AGX Orin
(MAXN power mode) 은 Orin Nano CUDA 대비 decode 단계 (seq=64) per-layer
시간이 약 16 배 빠르다. 균질한 fleet 에서 layer placement 는 단순한
반올림 문제이지만, 16 배 이종 환경에서는 placement 가 시스템 전체
throughput 을 좌우한다. 둘째, \textbf{신뢰성}: edge board 는 빈번히
crash 하며 SD card 가 가득 차거나 network 가 끊긴다. 본 연구의
measurement campaign 중 다수의 board 에서 위 세 종류의 장애를 모두
경험했다. 장애를 예외 경로로 처리하는 placement 는 첫 worker crash
시 진행 중인 모든 stream 을 잃는다.

기존 시스템은 layer placement ($\psi$) 와 recovery routing ($R$) 을
별개 문제로 다룬다. EdgeShard 의 DP 는 어딘가에 모든 layer 의
복제본이 존재한다고 가정하지만 4\,GB Nano 에서는 그러한 redundancy
를 감당할 수 없다. Petals 의 greedy placement 는 heterogeneous fleet
에서 2.38 배의 throughput 손실을 초래하며~\cite{mei2025helix},
swarm-redundancy recovery 모델은 edge 에 존재하지 않는 여유 메모리를
전제한다. Jupiter 의 throughput-optimal DP 에는 recovery 메커니즘
자체가 없다. 본 논문의 systemic insight 는 \textbf{memory-tight edge
에서 $R$ 과 $\psi$ 가 coupled feasibility region 을 갖는다는 점}이다.
두 결정을 분리하면 feasibility 또는 performance 중 하나를 반드시
양보해야 한다.

본 논문 \sys{} (Recovery-Aware DP) 의 기여는 다음과 같다.
\begin{itemize}
  \item Backup memory 예약이 placement feasibility 검사에 통합된
        $\psi$+$R$ alternating DP. EdgeShard 의 latency mode
        ($\alpha\!=\!0$) 와 Jupiter 의 throughput mode ($\alpha\!=\!1$)
        가 단일 $\alpha$ knob 으로 통합된다.
  \item Coordinator 로 activation tensor 를 비동기 mirroring 하는
        cache, 그리고 gRPC trailer metadata 를 통해 heartbeat path 가
        backup 으로 substitute 한 후에도 진정으로 죽은 worker 를
        정확히 식별하는 chain-aware failure attribution.
  \item \texttt{ResultReady} reverse channel 을 갖춘 asynchronous
        chain forwarding. Chain length 와 무관하게 $C\!=\!16$ 에서
        $17$--$47\%$ 의 throughput 향상.
  \item 8 worker Jetson cluster 라이브 측정. OPT-350M 24 cell +
        Llama-3.2-1B 9 cell --- $L\!\succ\!T$ dominance 가 두 model
        size 에 걸쳐 $C\!\geq\!4$ 에서 유지됨. Worker SIGKILL 시
        \sys{}는 60/60 token 전달, recovery 없는 baseline 은 17--20
        token 에서 중단.
\end{itemize}

\subsection{Recovery-Aware DP ($\psi$+$R$ joint optimization)}

$L$ 개의 decoder layer 와 $|D|$ 개의 heterogeneous device 가 주어졌을
때, placement $\psi: \{1,\ldots,L\} \to D$ 는 layer 를 인접한 stage
로 partition 하여 각 stage 를 device 에 할당하며, recovery table
$R: D \to D$ 는 각 device 에 대해 해당 device 의 layer memory 를
미리 reserve 하는 backup peer 를 할당한다. 두 결정 모두 backup
reservation 을 \emph{포함하는} device 별 memory cap 을 만족해야 하며,
다음 cost function 을 최소화한다.
\begin{equation}\label{eq:rank}
  \mathrm{rank}(\psi) = (1{-}\alpha) \sum_{s \in \psi} T(s)
                       \,+\, \alpha \max_{s \in \psi} T(s)
\end{equation}
여기서 $T(s)$ 는 device $d_s$ 에서의 stage $s$ 의 compute time
이다. $\alpha\!=\!0$ 은 EdgeShard 의 latency mode (sum of stage times
$=$ 단일 stream TBT), $\alpha\!=\!1$ 은 Jupiter 의 throughput mode
(가장 느린 stage 가 throughput 을 제약) 에 해당한다. Operator 는 이
knob 을 \texttt{optimization\_mode = \{latency, throughput, blended\}}
alias 로 조작한다.

DP recurrence 와 memory feasibility constraint 는 다음과 같다.
\begin{equation}\label{eq:dp}
  f(j, d) = \min_{i,d'} \Bigl\{ f(i, d') + \mathrm{rank\_inc}(i{+}1, j, d) \Bigr\}
\end{equation}
\begin{equation}\label{eq:mem}
  \mathrm{mem}_\psi(d) + \sum_{p\,:\,R(p)=d} \mathrm{mem}_\psi(p) \leq \mathrm{cap}(d)
\end{equation}
식 (\ref{eq:mem}) 이 systemic 핵심이다. $R$ 이 $\psi$-DP 에 device
cap 을 통해 들어가므로, $R$ 의 변화가 feasible 한 $\psi$ 의 집합을
변화시키고 그 역도 성립한다. $\psi$ 를 먼저 정한 후 $R$ 을 결정하는
decoupled solver 는 memory-tight edge 에서 feasible 한 $R$ 이 없는
$\psi$ 를 선택할 수 있다.

알고리즘~\ref{alg:alt} 은 두 문제를 alternating 으로 풀어 joint
solution 을 얻는다. Inner $\psi$-DP 는 고정된 $R$ 에서 $O(L^2 |D|^2)$,
greedy $R$ pass 는 고정된 $\psi$ 에서 $O(|D|^2)$ 이다. Cost 가
monotonically 비증가이므로 유한 반복 후 종료가 보장되며, 본 연구의
모든 fleet 에서 3 회 이내에 수렴했다.

\begin{algorithm}[t]
  \caption{Alternating $\psi$+$R$ optimization}
  \label{alg:alt}
  \begin{algorithmic}[1]
    \State $\psi_0 \gets \mathrm{greedy\text{-}placement}(D, L, \alpha)$
    \State $R_0 \gets \mathrm{greedy\text{-}backup}(\psi_0)$
    \State $k \gets 0$
    \Repeat
      \State $\psi_{k+1} \gets \mathrm{DP}(D, L, R_k, \alpha)$
      \Comment{식 (\ref{eq:dp}), (\ref{eq:mem})}
      \State $R_{k+1} \gets \mathrm{greedy\text{-}backup}(\psi_{k+1})$
      \State $k \gets k + 1$
    \Until{$\mathrm{rank}(\psi_k) \geq \mathrm{rank}(\psi_{k-1})$}
    \State \Return $(\psi_{k-1}, R_{k-1})$
  \end{algorithmic}
\end{algorithm}

\subsection{Mirror cache 와 chain-aware recovery}

Sync chain forwarding 에서 coordinator 는 chain head 의 input 만을
local 에 갖는다. Mid-chain worker 가 죽으면 coordinator 는 backup 으로
replay 할 activation history 가 없어 진행 중인 stream 이 손실된다.

\textbf{Mirror cache.} 각 worker 는 자신의 stage 를 실행하기 전에
들어온 activation tensor 와 \texttt{(request\_id, position)} key 를
coordinator 에 단방향 \texttt{MirrorActivation} RPC 로 전송한다.
Coordinator 는 position-keyed dictionary 에 저장하며, insert 는
idempotent 이라 중복 retry 와 out-of-order 도착을 자동 흡수한다.
비용은 non-head stage 당 단방향 RPC 한 번 (본 fleet 평균 1.2\,ms).
8-token Generate 의 산술 검증: 3-stage chain 에서 정확히 16 개의
mirror push (8 step $\times$ non-first stage 2 개).

\textbf{Trailer 기반 attribution.} Worker 의 downstream
\texttt{RunStage} 가 RpcError 를 발생시키면 upstream worker 는 실패한
stage 의 \texttt{(start\_layer, end\_layer)} 를 gRPC trailer 에
stamp 한 후 \texttt{UNAVAILABLE} 로 re-abort 한다. Coordinator 는
trailer 를 읽어 \emph{원본} placement $\psi_0$ 에서 --- 현재 execution
plan 이 아닌 --- lookup 한다. 이것이 중요한 이유: heartbeat path 가
이미 backup 을 새 chain head 로 substitute 했을 수 있는데, 그 substitute
된 worker 에 책임을 묻는 것은 healthy worker 를 mark-as-dead 하는
오류가 된다. Trailer 는 $R$ 이 이미 수행한 rewiring 과 무관하게
진정으로 죽은 stage 의 identity 를 운반한다.

\subsection{Asynchronous chain forwarding}

Sync chain 의 hidden cost 는 부하 측정 후 발견되었다. $C$ 개의
concurrent stream 이 각각 모든 $N$ 개의 chain stage 에서 하나의
gRPC handler thread 를 \emph{chain 전체 시간 동안} 점유한다. 즉
$CN$ 개의 thread 가 동시 점유되며, throughput-optimal placement 의
pipeline parallelism 이 실제로 발현되지 않는다.

Async chain 은 call pattern 을 뒤집는다. Worker 는 next-hop
\texttt{RunStage} 를 bounded thread pool 에 dispatch 한 후 즉시 빈
response 로 upstream caller 에게 ACK 한다. 각 handler thread 는
자신의 작업이 끝나면 즉시 해제된다. Chain tail 은 response chain 을
통해 결과를 되돌리는 대신 coordinator 에 \texttt{ResultReady} 를 직접
호출하여 최종 activation 을 전달한다. Coordinator 는
\texttt{(request\_id, position)} 별 \texttt{Event} 를 30\,s timeout
으로 대기한다.

Async mode 의 대가는 trailer-based attribution 이 불가능해진다는
점이다 --- response chain 이 이미 unwound 되어 trailer 를 stamp 할
수 없다. Coordinator 는 heartbeat (보통 5\,s 이내) 또는 30\,s
ResultReady timeout 으로 recovery 하며, 진정으로 죽은 worker 대신
chain head 가 표시될 수 있다. $\psi$+$R$ feasibility guarantee 가
correctness 를 유지하지만 (모든 token 일관 전달), recovery 는
heartbeat 가 race 에서 질 경우 한 hop 의 추가 비용을 지불한다.
Operator 는 \texttt{chain\_mode = sync $\mid$ async} knob 으로
trade-off 를 명시적으로 선택한다.

\section{실  험}
% =======================================================================

\textbf{환경.} 8-worker Jetson cluster (Orin Nano 8\,GB 6 대,
AGX Orin MAXN 1 대, AGX Xavier 1 대) 와 Mac coordinator 가 동일 LAN
상에 위치한다. 세 compute tier 를 decode step (seq=64) 에서 측정:
Nano CPU ($\sim$42\,ms/layer), AGX CPU ($\sim$17.6\,ms/layer),
Nano CUDA ($\sim$1.5\,ms/layer). AGX Orin MAXN 은 Nano CUDA 대비 동일
decode 점에서 약 16 배 빠르다.

\textbf{Model.} OPT-350M (24 layer, hidden 1024, fp16) 을 주 model
로, Llama-3.2-1B (16 layer, hidden 2048, fp16) 을 model-size
generalisation 검증용으로 사용했다. Llama 는 sharded safetensors
loader 로 적재된다.

\textbf{Workload.} Greedy decoding (\texttt{temperature=0}),
\texttt{max\_tokens} 은 실험별 가변 (concurrent sweep 30, recovery 60).
Concurrency 측정은 \texttt{measure\_concurrent.py}, recovery 측정은
\texttt{run\_phase3\_recovery.py} 가 담당한다. 모든 cell 의 결과는
\texttt{experiments/results/} 에 JSON 형태로 저장된다.

sub-matrix 에서의 throughput (tok/s, 클수록 좋음) 과 TBT p50 (ms,
작을수록 좋음) 을 보여준다.

\textbf{발견 1: OPT-350M 24 cell 모두에서 $L \succ T$.} Sync 끼리
(T+sync vs L+sync), async 끼리 (T+async vs L+async) 짝지어 비교 시
모든 24 점에서 $L$ 이 $T$ 를 throughput 면에서 압도한다. 최대 격차는
4-stage chain $C\!=\!4$ async cell 로, L+async ($23.91$\,tok/s) 가
T+async ($9.79$) 의 $2.4\times$ 이며 TBT p50 는 $2.8\times$ 낮다
($145$\,ms vs $406$\,ms).

\textbf{발견 2: Async $\succ$ sync ($C\!\geq\!4$, 단 T-placement
4-stage $C\!=\!4$ 예외).} 모든 $L$ row $C\!\geq\!4$ 에서 async 가
sync 를 압도한다. 유일한 예외는 T-placement 4-stage $C\!=\!4$
($10.71 \to 9.79$ tok/s, $-9\%$) 이며, 각 stage 의 layer 수가
1--2 개로 적을 때 chain-hop overhead 가 async 의 overlap 여유를
잡아먹기 때문이다.

\textbf{발견 3: Async gain 은 chain-length-independent.} T-placement
$C\!=\!16$ 에서 sync $\to$ async 전환 시 3-stage 는 $+47\%$
($23.49 \to 34.49$), 4-stage 는 $+46\%$ ($24.47 \to 35.69$). Sync
chain cost 는 concurrency 에 비례하지만 chain length 에는 비례하지
않는다.

\textbf{발견 4: Model-size generalisation + $C\!=\!1$ cross-over.}
3 배 큰 Llama-3.2-1B 에서 async $\succ$ sync 는 T row 에서 유지
($C\!=\!16$: $21.84 \to 30.56$, $+40\%$), $L \succeq T$ 는
$C\!\geq\!4$ 에서 유지 (L+async@C=4 가 best Llama cell, T+async 대비
$+12\%$). 새로운 관찰: $C\!=\!1$ single stream 에서 처음으로 T+async
가 L+async 를 throughput 에서 누른다 ($3.74$ vs $3.05$ tok/s,
$-18\%$). 그러나 TBT p50 는 여전히 $L$ 우위 ($174$ vs $261$\,ms,
$-33\%$) --- operator 관점의 responsiveness 에서는 $L$ 이 이긴다.
직관: 큰 model single stream 에서 stage compute 가 chain-hop cost
를 압도하면 $L$ 의 fast-device-heavy placement 가 그 single stage 를
throughput-bottlenecking critical path 로 만든다. Multi-stream 은
hop cost 를 amortise 하여 $L$ 의 pipeline-saturation 우위가 복귀한다.

\textbf{Recovery 결과.} Star topology 에서 worker SIGKILL 후 \sys{} 는
5/5 시행 모두 60/60 token 을 일관되게 전달했고, recovery wall-clock
평균 $617$\,ms, p95 $670$\,ms 였다. Recovery 가 없는 baseline 3 종
(greedy, uniform, Jupiter-DP) 은 SIGKILL 경계에서 모든 진행 중 token
손실 후 stream 이 중단되었다. 4-stage chain topology 에서도
sync/async 모두 60/60 token 을 전달한다.

\section{결  론}
% =======================================================================

본 논문은 layer placement 와 recovery routing 을 단일 alternating DP
로 통합한 \sys{} 시스템을 제안하고, 두 runtime 기법 (asynchronous
mirror cache, asynchronous chain forwarding) 으로 실 edge fleet 에서
joint optimization 의 운용 가능성을 확보했다. OPT-350M 24-cell matrix
는 $\psi$+$R$ joint optimization 에 의한 $L$ 우위가 \emph{구조적}이며
특정 topology 나 runtime 에 의존하지 않음을 보였고, 3 배 큰
Llama-3.2-1B sub-matrix 는 동일 pattern 이 model size 에 걸쳐
$C\!\geq\!4$ 에서 유지됨을 확인했다. $C\!=\!1$ 큰 model 의 cross-over
는 claim 을 명확히 한정한다. Async chain 은 $C\!=\!16$ 에서
$17$--$47\%$ throughput 향상을 가져오면서도 $C\!\geq\!4$ 의 placement
순서를 결코 뒤집지 않아, 두 knob 이 operator 에게 orthogonal 한
trade-off 를 제공함을 보였다.

향후 과제는 (i) $R$ 을 single backup 에서 backup list 로 확장한
cascading failure 대응, (ii) 7B INT4 의 memory-bound regime 측정
(본 1B 측정에서 이미 Nano memory pressure 가 운용 한계로 노출됨),
(iii) cost function 의 marginal-layer term 으로 현재 $2$--$4\%$ 의
predicted-vs-measured 격차 축소가 포함된다.
