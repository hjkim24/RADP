# Progress Report — 디자인 시스템

주간 진행보고 덱의 규격. **매주 이 문서 + `template/radp-progress-template.pptx`를 기준으로 만든다.**

목적은 "예쁘게"가 아니라 **매주 같은 결과가 나오게** 하는 것. 그래서 규칙을 형용사가 아니라 숫자로 적는다.
("간결하게", "깔끔하게" 같은 지시는 매번 다른 결과가 나온다.)

---

## 0. 매주 워크플로우

1. `template/radp-progress-template.pptx` 복사 → `Progress Report_MMDD.pptx`
2. §9 인테이크 폼을 채운다
3. Claude for PowerPoint 에게: **이 문서 §1~§8 + 채운 인테이크 폼**을 전달
4. §10 체크리스트로 검수

템플릿에는 패턴별 예시 슬라이드가 들어 있다. **새로 만들지 말고 해당 패턴 슬라이드를 복제해서 채운다.**

덱 `.pptx` 는 추적하지 않지만 **주간 프롬프트 `ppt/prompt_MMDD.md` 는 커밋한다.**
매주 어떤 수치와 주장을 슬라이드에 올렸는지가 거기 남는다 — 나중에 페이퍼 근거를
되짚을 때 덱보다 이쪽이 검색된다.

상단 밴드 문구는 아래 그대로. 순서 고정, 임의 추가 금지.

|---|---|---|

## 2. 슬라이드 해부 (좌표 고정)

단위 inch, 캔버스 13.33 × 7.50 (16:9).

```
섹션 밴드      L 0.00  T 0.00  W 13.33  H 0.52    28pt  흰 글자 / 배경 202843
워크스트림     L 0.05  T 0.60  W  6.00  H 0.50    24pt  #0070C0
소제목         L 0.05  T 1.10  W  8.00  H 0.37    16pt  **굵게**
콘텐츠 영역    y 1.75 ~ 6.35            (좌여백 0.63 / 우여백 0.63)
캡션           콘텐츠 하단 바로 아래                12pt
쪽번호         L11.17  T 7.22  W  0.70  H 0.26    12pt
```

**섹션 밴드는 배경이 있는 도형이다.** `202843` 짙은 남색으로 채운 텍스트박스 +
흰 글자. 배경 없는 투명 텍스트박스로 만들면 덱 전체에서 헤더가 사라진 것처럼 보인다.

**표지(1번)는 건드리지 않는다.** 로고·문구·좌표·**폰트 전부 원본 그대로**
(Times New Roman 32/12pt + Arial Narrow). 발표자 정보 텍스트만 갈아끼운다.
본문의 Roboto 통일은 2번 슬라이드부터 적용된다.

## 3. 타이포그래피

**모든 텍스트는 아래 7개 역할 중 하나다.** 여기 없는 크기를 새로 만들지 않는다.

| 역할 | 크기 | 굵게 | 색 | 비고 |
|---|---|---|---|---|
| 섹션 밴드 | 28pt | — | 흰색 (배경 `202843`) | 문구는 §1 고정 |
| 워크스트림 제목 | 24pt | 아니오 | `0070C0` | |
| 소제목 | 16pt | **예** | `404040` | 워크스트림 아래 한 줄 |
| 강조 한 줄 | 20pt | 아니오 | `404040` | 슬라이드당 최대 1개 |
| 본문 · 라벨 | **16pt** | 아니오 | `404040` | 압도적 다수. 기본값 |
| 표 (§6) | 16pt / 행 5개 이상이면 14pt | 헤더만 | 헤더 흰색, 본문 `404040` | |
| 캡션 · 참고문헌 | 12pt | 아니오 | `404040` | |

그림 안 글자는 슬라이드가 아니라 그림의 규격을 따른다 (§7.1: 축 14 / 눈금 12 /
범례 12 / 주석 13pt).

### 굵게를 쓰는 자리
소제목, 표 헤더, 표 안에서 강조할 셀, 결론 한 줄. **그 외에는 쓰지 않는다.**
굵게가 슬라이드마다 서너 군데씩 흩어지면 아무 데도 강조가 아니게 된다.
색으로 강조하지 않는다 — 강조는 굵게로만 한다 (§4).

폰트는 **Roboto 하나** (2번 슬라이드부터. 표지는 원본 폰트 고정 — §2 참고).
예외는 등폭이 필요한 수식/코드 블록뿐 (`Consolas`, 16pt).
Roboto 가 설치돼 있어야 한다. 없으면 PowerPoint 가 임의 대체 폰트로 렌더링해서
자간·줄바꿈이 어긋난다.

## 4. 색

**본문 텍스트는 전부 `404040` 한 색.** 강조는 색이 아니라 **굵게**로 한다.

| 역할 | 값 | 쓰는 곳 |
|---|---|---|
| 본문 | `404040` (dk1) | 모든 텍스트 |
| 구조 | `202843` | 섹션 밴드 배경, 표 헤더 배경 (글자는 흰색) |
| 제목 강조 | `0070C0` | 워크스트림 제목, 결론 강조 |
| 경고 · 문제 | `FF0000` | 버그/한계/비용 표시. 슬라이드당 1회 |

이 네 색이 **원본 랩 템플릿이 실제로 쓰던 색**이다 (색 조사: fill `202843` ×22,
text `FF0000` ×22, text `0070C0` ×15). 테마 accent 팔레트가 아니라 이쪽을 따른다.
팔레트 밖 색 금지.

### 반복 대상 색 고정 (주 단위 비교 가능성)
같은 대상은 **매주 같은 색**으로 그린다. 청중이 색으로 대상을 기억하게 하기 위함.

| 대상 | 색 | 이유 |
|---|---|---|
| full-replay | `FF0000` | 제일 비싼 쪽에 시선이 먼저 가야 대비가 산다 |
| surgical | `202843` | 중간. 구조색 |
| parity | `0070C0` | 덱이 제목에 쓰는 강조 파랑 = 이번 결론 |
| baseline / 복구 없음 | `808080` | |

## 5. 이 랩은 시각물 우선이다

원본 템플릿 24장에 **그림 23 + 표 5**. 콘텐츠 슬라이드당 시각물 1개꼴이고, 텍스트는 그림 주변의 짧은 라벨이지 불릿 목록이 아니다.

**규칙: 콘텐츠 슬라이드는 시각물 1개를 기본으로 잡는다.** 시각물 없이 불릿만 있는 슬라이드는 이 덱에서 비어 보인다(2026-07-21 덱에서 실제로 겪음).

시각물이 정말 없으면 표로 대체하고, 표도 없으면 그 내용은 다른 슬라이드에 합친다.

## 6. 표 규격

- **최대 4행 × 3열.** 넘으면 잘라서 두 장으로. (원본의 9×3 은 읽히지 않는다)
- 헤더: **굵게 흰 글자**, 배경 `202843` (원본 표 헤더와 같은 색). 본문 16pt,
  행이 5개 이상이면 14pt
- 본문 행은 남색을 흰색에 섞어 만든 옅은 두 톤으로 번갈아: `E8EAF0` / `F6F7F9`.
  **PowerPoint 기본 표 스타일의 밴딩(초록)을 반드시 끌 것** — `tblPr`의
  `bandRow`/`firstRow` 플래그를 0으로 내리고 셀마다 직접 칠한다. 안 그러면
  테마 accent 색이 되살아나 덱과 따로 논다
- 숫자는 **오른쪽 정렬**, 단위는 셀이 아니라 **헤더**에 (`TTR (초)`)
- 세로 괘선 없음. 헤더 아래 가로선 1개만
- 강조는 **굵게**로. 셀 배경색으로 강조하지 않는다
- 표 아래 **결론 한 줄**을 반드시 붙인다 (`• 표에서 읽어야 할 것`)

## 7. 그림 · 차트 규격

### 7.1 슬라이드용 그림은 논문용과 다르게 만든다
`paper/figures/_common.py`는 논문 2단 조판 기준 **8pt** 폰트다. 이걸 그대로 슬라이드에 넣으면 글자가 안 보인다.

**규칙: 슬라이드에 놓일 크기 그대로 만들고, 폰트를 덱 스케일로 올린다.**

```
figsize      = 슬라이드에서 차지할 크기 그대로 (예: 7.4 × 4.6 in)
축 라벨       14pt
눈금          12pt
범례          12pt
주석/수치      13pt
선 두께        2.0
dpi          300 (png) / pdf 동시 출력
```
전폭 그림(콘텐츠 영역 전체)을 쓸 땐 좌측 라벨을 붙이지 않는다. 그림 자체가
설명이면 옆에 라벨을 또 붙이는 순간 같은 말이 두 번 나온다.

1:1 크기로 만들면 PowerPoint 에서 확대·축소가 없으므로 글자 크기가 덱과 일치한다.
**PowerPoint 에서 그림을 늘리거나 줄이지 않는다.** `savefig(bbox_inches="tight")`
가 여백을 잘라내므로 실제 크기는 figsize 보다 조금 작다(7.4 → 7.05 in).
그 잘린 크기 그대로, 배율 100% 로 얹는다.

템플릿 4번 슬라이드에 이 규격대로 만든 실물 예시가 들어 있다. 마지막 장
`그림 규격`은 이 절을 슬라이드로 옮겨둔 참고 카드다 (발표 전 삭제).

### 7.2 그림 안에 넣지 않을 것
- **제목** — 슬라이드 제목이 그 역할을 한다. 중복이면 슬라이드 제목을 지우는 게 아니라 그림 제목을 지운다
- 범례 박스를 축 밖에 두어 여백을 먹는 것 — 축 안에 넣는다
- 격자선 과다 — `alpha 0.3` 이하 옅게

### 7.3 그림 안 글자는 영어
슬라이드 본문은 한국어, **그림 안은 영어**로 통일한다. 그림은 논문에도 그대로
들어가므로 두 벌을 유지하지 않기 위함이고, `생존자`·`홉` 처럼 원어가 굳어 있는
용어를 억지로 옮기면 오히려 어색해진다 (`survivor`, `hop`).

### 7.4 색
§4의 **반복 대상 색 고정**을 따른다. matplotlib 기본색(`#1f77b4` 등) 대신 덱 팔레트를 쓴다. 그래야 슬라이드와 그림이 같은 덱으로 보인다.

### 7.5 캡션
그림 바로 아래 12pt 한 줄로 **환경 / 조건 / 유효 샘플 수**. 예:
`OPT-350M 24층 / 5-stage 이종 체인 / 15개 트라이얼 전부 유효`

## 8. 슬라이드 패턴 카탈로그

템플릿의 예시 슬라이드 번호와 대응한다. 새 레이아웃을 발명하지 말고 여기서 고른다.

**템플릿은 뼈대가 아니라 애셋이다.** 아래 표의 "템플릿 N번"은 그 패턴의 견본이
어디 있는지를 가리킬 뿐, 덱에 한 장씩만 넣으라는 뜻이 아니다.

- 같은 패턴을 **몇 번이든 복제**해서 쓴다 (P2 ×4, P4 ×2 …)
- 이번 주에 안 쓰는 패턴 슬라이드는 **지운다** (빈 껍데기를 남기지 않는다)
- 총 장수는 **내용이 정한다.** 템플릿이 8장이라고 8장을 채울 필요 없다
- 고정된 건 §1의 섹션 4개(문구·순서)와 §2~§4·§6·§7의 좌표·폰트·색·규격뿐이다

| 패턴 | 템플릿 | 용도 | 구성 |
|---|---|---|---|
| **P1 피드백↔대응** | 3번 | §1 요약 | 2열 표. 좌=지적, 우=대응 |
| **P2 그림 우선** | 4번 | §2 주력 | 좌 라벨 3줄 + 우 대형 그림 + 캡션 |
| **P3 2단 비교** | 5번 | §2 | 좌/우 시각물 2개 + 하단 해석 1줄 |
| **P4 표 중심** | 6번 | §2 수치 | 3열 표 + 결론 1줄 |
| **P5 계획** | 7번 | §3 | 불릿 20pt |
| **P6 참고문헌** | 8번 | §4 | 12pt 목록 |
| *(참고 카드)* | 9번 | — | 그림 규격 요약. **발표 전 삭제** |

### §2 안의 순서 — 새 기술이 처음 들어가는 주

패턴을 고르기 전에 **순서**를 먼저 정한다. 진행보고는 시간순으로 쓰기 쉬운데,
청중은 시간순으로 이해하지 않는다.

새 기법·새 구조가 이번 주에 처음 등장하면 이 순서를 쓴다:

| | 슬라이드 | 답하는 질문 |
|---|---|---|
| a | 기존 방식과 그 한계 | 왜 새로 만들었나 |
| b | 새 기술의 원리 | 이게 뭔가 |
| c | **장단점 비교** | 대가로 뭘 내나 |
| d | 적용 범위 · 예외 | 어디까지 되나 |
| e~ | 실측 | 실제로 얼마나 |

**비교표와 숫자를 원리보다 앞에 두지 않는다.** 처음 보는 기법의 수치를 먼저
보여주면 청중은 모르는 것을 평가하게 되고, 원리 슬라이드에 가서야 앞 슬라이드를
되짚는다.

**(c) 를 빼지 않는다.** 새 기술 슬라이드는 이기는 그림만 남기기 쉽다. 얻는 것과
내는 대가를 같은 표에 나란히 둔다 — 질의응답에서 나올 질문이 그것이고, 먼저
말하는 편이 낫다. 대가가 정말 없으면 왜 없는지를 쓴다.

이미 아는 기술의 후속 측정이면 (a)(b)(c) 는 생략하고 (e) 부터 간다.

### 밀도 규칙
- 주 불릿 **3~5개**, 각 불릿 아래 **보조 1줄까지** (2단계까지만)
- 한 줄 **40자 이내**
- 문단·줄글 금지. 보조 줄도 한 줄로 끝낸다
- 상세 맥락은 슬라이드가 아니라 **발표자 노트**로. 단 **숫자와 근거는 슬라이드에 올린다**

### 문체 — 음슴체 또는 명사 종결

슬라이드는 문서가 아니라 말할 때 쓰는 지지대임. 서술체로 쓰면 발표자가 읽게 되고,
읽기 시작하면 청중은 슬라이드를 보지 발표자를 안 봄.

- **종결은 음슴체(`-함`, `-됨`, `-임`) 또는 명사로.** 존댓말·서술체 금지
- ✗ `parity 는 깊이에 무관하게 동작합니다` → ✓ `깊이 무관`
- ✗ `버그를 두 개 발견했습니다` → ✓ `구현 중 버그 2건` / `버그 2건 발견함`
- ✗ `이 결과는 중요한 의미를 가집니다` → 근거 없는 의미 부여. 삭제하고 숫자만 남김

**AI 어투 금지.** 아래는 실제로 자주 새어 들어오는 것들:

| 금지 | 대신 |
|---|---|
| `~를 통해`, `~를 활용하여` | `~로` |
| `극대화`, `최적화`, `혁신적`, `핵심적`, `강력한` | 숫자를 적음 |
| `A가 아니라 B다` 식의 반전 구문 | B 를 그냥 주장으로 씀 |
| `~할 수 있습니다`, `~로 보입니다` | 단정하거나 삭제 |
| 형용사로 하는 강조 (`대폭`, `크게`, `현저히`) | `164 → 0.87 ms/pos` |

**영단어 뒤 조사는 붙여 쓴다.** 띄우면 조사가 다음 단어처럼 읽혀 한 박자 늦게 이해됨.

- ✗ `parity 는`, `stage 가`, `KV 를`, `hop 이`, `GhostServe 가` 
- ✓ `parity는`, `stage가`, `KV를`, `hop이`, `GhostServe가`
- 숫자·기호로 끝나도 같음: `on-1은`, `100%로`, `P=4에서`

**형용사 하나에 숫자 하나.** 뒤에 숫자·이름·비교 대상이 없는 형용사는 지움.
`빠르다`는 정보가 아님. `0.87 ms/pos`가 정보임.

### 슬라이드 제목은 라벨이 아니라 주장
- ✗ `실측 결과` → ✓ `parity는 깊이를 안 탄다`
- 청중이 그림을 볼 때 **무엇을 확인해야 하는지** 알고 보게 된다

### 자주 겪는 것
- **이미지 삽입 실패** — 로컬 파일을 못 집어올 때가 있다. 그러면 자리와 크기만 잡아두게 하고 직접 끌어다 놓는다. 프롬프트에 "안 되면 자리만 잡고 알려줘"를 넣어두면 조용히 넘어가지 않는다.
